# Wording, dates and money

The app is English. The message table and the translator are built so that a Hindi file can be
added without touching call sites, and the date, financial-year and money helpers render Indian
conventions in one place.

## Messages

`apps/web/src/shared/i18n/messages/en.json` is a flat object of keys to English strings. Keys
are namespaced by feature (`common.appName`, `nav.primary`, `home.signIn`, `sitemap.title`,
`legal.draft`, `notAvailable.title`, `error.retry`, `admin.tools`, `design.intro`, `role.owner`,
`status.live`, `date.inDays`, `money.prefix`), lower camel case after the dot, and a message uses
`{name}` placeholders for values. `index.ts` exports:

- `t(key, vars?)`: the English translator. `key` is typed as `keyof typeof en`, so a misspelt
  key is a type error; `interpolate` replaces `{name}` with `vars.name` and leaves an unknown
  placeholder as written.
- `createTranslator(locale)` for `"en"` or `"hi"`: a translator over that locale's overrides,
  falling back to English key by key. Hindi has no file yet, so its translator is English
  today; when `messages/hi.json` exists it registers here and a test asserts it has no key
  outside the English set.
- `isMessageKey`, `isLocale`, `messages`, `DEFAULT_LOCALE`, `LOCALES`.

`index.test.ts` scans every `.ts` and `.tsx` file under `src` for `t("...")` literals and fails
when one is missing from `en.json`, so a key is added to the file in the same change as its
first use.

What goes through `t()`: chrome and system strings (navigation labels, buttons, banners, the
not-found and error pages, the sitemap's column headings, the catalogue's own labels). What does
not: the registry's screen titles and navigation group labels, which are English data in
`shared/config` (those files load under plain Node, where a JSON import would need an import
attribute), and the role, status and owner labels the `entities/screen` mappers produce. Enum
values that arrive from a service are rendered with `humanise()`, never with a key per value.

## Enum values

`shared/lib/humanise.ts` turns `snake_case` or `kebab-case` values into sentences
(`not_started` to "Not started", `ca_admin` to "CA admin") with the spellings that stay
upper-case (QRMP, GSTIN, GST, GSTR, HSN, SEZ, LLP, HUF, ISD, TDS, TCS, PAN, CA, FY, ID, API,
LLM, OTP, MFA, SSO, PDF, URL, WhatsApp). `titleCase` capitalises every word. Regulatory wording
itself never comes from here; it comes from service data, `docs/legal` or the ontology
(`GET /v1/ontology` through `server/ontology.ts`, which words every attribute and value).

## Dates

`shared/lib/dates.ts` renders in `Asia/Kolkata` with `en-IN` conventions and never trusts the
browser's zone for a due date. Services exchange ISO 8601 strings: dates as `YYYY-MM-DD` (a
"date key") and instants with an offset.

- `formatDate("2026-04-10")` gives `10 Apr 2026`; `formatDateTime(instant)` gives
  `10 Apr 2026, 5:30 pm IST`.
- `istDateKey(instant)` and `todayKey(now?)` give the IST calendar date; `daysBetween`,
  `addDaysToKey` and `isDateKey` work on date keys without float or zone surprises.
- `dueRelative(dueKey, now?)` answers `today`, `tomorrow`, `in_days` or `overdue` with the
  count; `formatDueDate(dueKey, words, now?)` renders `10 Apr 2026 (in 3 days)` with the words
  supplied by the caller (from `t("date.today")`, `t("date.inDays", { count })` and so on), so
  the phrase can be translated.

## Financial years

`shared/lib/financial-year.ts`: an Indian financial year runs from 1 April to 31 March and is
labelled by its start year and the last two digits of the end year, `2026-27`.
`financialYearOf(dateKey)`, `currentFinancialYear(now?)`, `financialYearLabel`,
`parseFinancialYearLabel` (rejects a wrong end year), `financialYearRange` (`from` and `to` date
keys), `nextFinancialYear`, `previousFinancialYear`. The label format is what the profile
service's `fy=` query parameter takes.

## Money

Amounts arrive from services as decimal strings with two decimals (`"1499.00"`) or as integer
paise. `shared/lib/decimal.ts` converts and computes with `bigint` (`toPaise`, `fromPaise`,
`addAmounts`, `subtractAmounts`, `compareAmounts`, `isAmount`) and never with floats.
`shared/lib/money.ts` renders: `formatPaise(149900)` gives `Rs 1,499.00` with `en-IN` grouping
(lakhs and crores), `formatAmount("1499.00")` the same from a string, `paiseToAmount` the
string a service expects. The prefix is the plain `Rs` so no font or encoding question arises
in a notification or a plain-text export.

## Identifiers

`shared/lib/identifiers.ts` validates the identifiers the app shows or accepts (`isGstin`,
`isPan`, `isUuid`, `isE164`, `isHexId`), derives `gstinStateCode` and `panOfGstin`, normalises
case and whitespace, and masks an identifier for display (`maskIdentifier`). None of these
appear in a URL: identifiers and questions travel in request bodies or httpOnly cookies, and
route parameters are opaque ids.
