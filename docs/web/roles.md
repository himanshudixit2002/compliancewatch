# Roles

Generated by `pnpm --filter web roles:gen` from `apps/web/src/shared/config/roles.ts`,
`permissions.ts` and `screens.ts`. Do not edit by hand: `pnpm --filter web roles:check` and the
vitest test `src/test/roles-doc.test.ts` fail when this file and the configuration differ.
`roles-parity.test.ts` holds `roles.ts` to the kernel's `domain_kernel/access.py` and identity's
`domain/tenancy.py`, so what is here is what every service enforces.

## Roles and tenant kinds

A person holds one or more roles in one tenant; the tenant's kind decides which roles it may
give. The sets are what the gates and the capabilities are written in: tenant members act
inside a business or a CA firm, tenant admins manage its people (the last active one cannot be
demoted or disabled), the regulatory roles open `/admin`, and the roles that need a second
factor sign in only with one (identity refuses the exchange otherwise, and the admin tools and
the team pages send a session without one to `/account/mfa`).

| Role              | Tenant kinds      | Sets                                               | First user                       |
| ----------------- | ----------------- | -------------------------------------------------- | -------------------------------- |
| `owner`           | business          | tenant member, tenant admin                        | first user of a business tenant  |
| `staff`           | business          | tenant member                                      |                                  |
| `ca_admin`        | ca_firm           | tenant member, tenant admin, needs a second factor | first user of a ca_firm tenant   |
| `ca_staff`        | ca_firm           | tenant member                                      |                                  |
| `compliance_lead` | business, ca_firm | tenant member                                      |                                  |
| `analyst`         | internal          | regulatory, needs a second factor                  |                                  |
| `reviewer`        | internal          | regulatory, needs a second factor                  |                                  |
| `admin`           | internal          | regulatory, needs a second factor                  | first user of an internal tenant |
